# Alpha 0.0.4.3 — Texture Core Stability Update

Alpha `0.0.4.3` is the final stabilization and polish release for the first Texture Core phase. It adds no large editor system and does not begin Materials Core or Animation Core.

## UV 2.0 fixes

- UV move and resize use the atlas dimensions and precision captured when the gesture begins, so a rapid context change cannot reinterpret the final pointer delta.
- Every gesture and Rotate, Flip, Fit, Reset, Copy, Paste, and Auto Box result is normalized to finite values and clamped inside the texture atlas.
- All supported precision modes—0.25, 0.5, 1, 2, and 4 px—use deterministic decimal rounding.
- Auto Box UV preserves quarter-pixel detail for decimal and very small cuboids, scales very large cuboids to the atlas, and keeps all six islands bounded.
- Multi-face selection is remembered per cuboid and no longer collapses merely because the active face or material changes.
- Multi-face material assignment and batch UV updates are transactional and skip unchanged records.
- The duplicated active-island commit path was removed. Rapid drafts are coalesced per binding and stale asynchronous responses cannot replace a newer draft.
- Replacing a texture with a different atlas size atomically normalizes every linked binding.

## Paint 2.0 fixes

- Fast Pencil and Eraser gestures consume coalesced pointer samples and interpolate every pixel between samples.
- A 6 CSS-pixel touch deadzone preserves taps; a second touch cancels a pending stroke and gives pinch zoom/two-finger pan ownership of the gesture.
- Pointer capture, cancellation, lost capture, page hide, mode changes, and editor teardown all finalize or flush work predictably.
- X/Y mirroring reflects each covered pixel, fixing shifted output from even 2/4/8 px brushes.
- Fill, Replace Color, Line, Rectangle, Undo, and Redo avoid adding identical history states. History remains capped at 64 meaningful states.
- Paint autosaves after 800 ms of inactivity without repetitive success notifications.
- Each Paint save carries its originating texture-asset ID, preventing pixels from one canvas being stored in a newly selected material during a fast switch.
- Canvas rendering remains nearest-neighbor and pixel-perfect for the supported 64×64 and 128×128 workflows.

## Mobile and Safari hardening

- UV, Paint, preview, and divider gestures handle `pointercancel`, `lostpointercapture`, safe capture/release, and fingers temporarily leaving the visual target.
- Editor surfaces suppress page scrolling, text selection, and long-press context menus without disabling browser zoom globally.
- Editable controls keep a 16 CSS-pixel font size and primary editor controls use approximately 44×44 CSS-pixel targets.
- Safe-area padding, compact portrait widths, short landscape heights, scrolling tool strips, inspector bounds, and long translated labels were reviewed for overflow.
- Route/mode changes wait for Paint and UV persistence. A failed local save remains visibly unsaved and prevents silent navigation loss.

## Preview, performance, and cleanup

- The Texture Core preview raycasts only visible cuboids, highlights the selected face, and fits rotated visible geometry rather than unrotated model dimensions.
- Texture loading uses generation guards, nearest filtering, and immediately revoked runtime object URLs.
- Preview materials are shared instead of allocating six unique materials per cuboid.
- Three.js scenes, meshes, geometries, materials, textures, controls, renderers, resize observers, pointer listeners, and WebGL contexts are released during teardown.
- Canvas history and Three.js runtime objects remain outside deep Vue reactivity.

## Persistence and compatibility

- Fully compatible with local Texture Core records created by Alpha `0.0.4.0`, `0.0.4.0.1`, and `0.0.4.2`.
- Database schema version 4 is unchanged. There is no IndexedDB reset and no destructive migration.
- Invalid legacy UV rectangles are repaired in place only when opened, preserving material, asset, cube, face, and binding identity.
- Local project duplication now copies and remaps materials, texture blobs, and model-specific bindings. Project deletion removes owned Texture Core data; model deletion removes only that model's bindings and keeps the reusable project material library.

## Behavioral changes

- Paint cannot begin until the selected material has a texture asset, avoiding an unsavable blank canvas.
- A texture imported at new dimensions may move or reduce an out-of-bounds UV island so it remains valid inside the new atlas.
- Normal Paint saves are quiet; the top status communicates Saved, Saving, Unsaved Paint, or Unsaved UV.

## Known limitations

- UV 2.0 edits cuboid face rectangles; arbitrary mesh/vertex UV editing is not implemented.
- Paint has no layers, lasso/selection, transforms, or advanced brushes.
- The lightweight 3D preview displays the active texture for authoring feedback; it is not the future Materials Core renderer.
- The current beta `.addonsstudio` portable package contract predates Texture Core and does not yet include materials, texture images, or face bindings. Local IndexedDB projects and local project duplication do preserve them.
- Automated mobile regression checks cover pointer ownership and responsive safeguards, but physical-device Safari behavior still depends on the iOS/PWA environment and should continue receiving real-device QA.

## Validation

Release validation on 2026-08-20 completed a clean `npm ci`, zero-warning ESLint, Vue-aware TypeScript checking, 35 Vitest files / 166 passing tests, a production PWA build, and a GitHub Pages `/addons-studio/` subpath build. CI, Pages deployment, and public-site status are also recorded in pull request #6 and the final release report.

The next major phase may begin Materials work only after this stabilization release is accepted.
