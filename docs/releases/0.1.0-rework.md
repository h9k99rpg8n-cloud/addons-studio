# Addons Studio Alpha 0.1.0 — Rework Update

The Rework Update rebuilds Addons Studio around its strongest role: a mobile-first Bedrock project hub for organization, guided creation, generated files, reusable resources, and specialist-tool integration.

## Product direction

Addons Studio no longer attempts to replace Blockbench or maintain a second model, UV, and texture-paint engine. Models and compatible images are stored in local project libraries and handed to the official Blockbench web application for specialized editing.

The implementation does not bundle or copy Blockbench GPL source. It uses original MIT-licensed Addons Studio adapters and Blockbench's documented URL parameters, with a safe file-download fallback for large payloads.

## Interface and identity

- Original yellow tile with a simplified block and crossed black creation tools.
- Graphite navigation, neutral surfaces, restrained yellow active states, and semantic status colors.
- Home, Create, Assets, Code, World, and Project navigation.
- Bottom navigation on phones and a side rail on larger screens.
- Safe-area-aware, 44-pixel touch targets and 16-pixel editable controls.
- Updated Home, workspace, projects, resource libraries, settings metadata, empty states, cards, PWA icons, and release experience.

## Working creation flows

### Models

- Create a starter 16×16×16 Bedrock geometry file.
- Import `.json`, `.geo.json`, and `.bbmodel`.
- Detect supported formats rather than accepting arbitrary JSON.
- Search, organize in folders, rename, move, download, delete, and open in Blockbench.
- Convert legacy Addons Studio model JSON to Bedrock geometry for the external handoff.

### Materials

- Import PNG/JPEG from the device picker.
- Preview, search, organize in folders, rename, move, duplicate, replace, and delete.
- Inspect project usage and open/download an image for Blockbench editing.
- No duplicate in-app paint editor is exposed.

### Blocks and Block Models

- Guided display name and namespaced identifier.
- English, Spanish, Portuguese, French, German, Japanese, and searchable custom locale codes.
- Same-face, top/side/bottom, or per-face project material assignment.
- Contextual light settings, Vibrant Visuals metadata warning, collision terminology, mining and movement settings, and optional recipe state.
- Lightweight cube preview and Bedrock source ZIP output with block JSON, language files, texture data, optional loot, and optional model geometry.

## Persistence and migration

Database schema 5 adds generic resources, resource folders, and resource assets. It does not reset or destructively migrate previous stores.

Legacy Model Core and Texture Core data remains in IndexedDB for compatibility. Project duplication and deletion understand both old and new records.

Project package format 2 includes Rework resources, resource folders, binary resource assets, project materials, texture images, and compatible legacy bindings. Format 1 packages remain importable. Every import creates new internal IDs and commits transactionally.

## Performance

The Three.js runtime and type dependencies are removed. Model/texture editor route chunks, permanent render loops, WebGL resources, and associated startup cost are no longer part of the Rework application.

## Known limitations

- Blockbench runs as an external web application; Addons Studio cannot change its cross-origin mobile interface or automatically receive edits back. Users re-import the saved file after editing.
- Model cards provide format and geometry metadata rather than an in-app WebGL render.
- Generated Block ZIP files are source resources, not a complete `.mcpack` or `.mcaddon` build.
- Recipes, Plugins, Functions, Items, Entities, Plants, Particles, Sounds, and Animations are shown only as non-interactive roadmap modules until their generators or integrations exist. World tools remain hidden until they are functional.
- Vibrant Visuals colored-light metadata is preserved but is not emitted as an unsupported block field.

## Validation

Release gates require a clean dependency install, lint, Vue/TypeScript checks, automated tests, production PWA build, GitHub Pages base-path inspection, and mobile viewport review before publication.
