# Addons Studio Alpha 0.0.4.0 — Texture Core Foundation

Alpha 0.0.4.0 opens the first generation of Texture Core while keeping Model Core responsible only for geometry.

## New project resources

### Materials

Materials is the reusable project-level library. A material can be used by multiple models without copying its texture.

The first Materials release supports:

- project-scoped material records and identifiers;
- PNG and JPEG texture import;
- blank 32×32 texture creation;
- circular material previews;
- a Quick Edit pixel canvas;
- Pencil, Eraser, Fill, and Eyedropper;
- 1, 2, 4, and 8-pixel brush sizes;
- pixel-perfect zoom;
- transparency checkerboard;
- Undo and Redo;
- saving edited textures back as PNG;
- deletion of a material together with its owned texture and bindings.

### Texture Core

Texture Core opens an existing Model Core resource and adds texture data without mutating its geometry.

The first workspace supports:

- model selection;
- lightweight loading state for geometry/material assets;
- live Three.js model preview;
- nearest-neighbor texture sampling;
- project material selection/creation;
- per-cube and per-face material bindings;
- initial UV rectangle metadata;
- UV Inspector information;
- built-in pixel editing with Pencil, Eraser, Fill, and Eyedropper;
- brush-size and zoom controls;
- texture Undo/Redo;
- PNG save.

## Storage architecture

IndexedDB schema 4 adds three dedicated stores:

- `materials` — reusable project-level material definitions;
- `textureAssets` — PNG/JPEG binary texture assets owned by the project;
- `textureBindings` — model/cube/face links from Model Core geometry to reusable materials and UV metadata.

This deliberately keeps binary images and Texture Core state out of `StudioModel`.

The ownership model is:

```text
Project
├── Materials
│   └── Texture Assets
└── Models
    └── Texture Bindings → Materials
```

One material can therefore be shared by multiple models while every model keeps its own face assignments.

## Mobile safety

Texture imports are validated before persistence. Alpha 0.0.4.0 accepts PNG/JPEG images up to 16 MB, 4096 pixels on either side, and 16 megapixels. The live preview uses a low-power renderer and crisp nearest-neighbor texture filtering.

## What is intentionally not included yet

This is Texture Core 0.1, not the finished texture engine. The following remain for later 0.0.4.x updates:

- Box UV and advanced Auto UV;
- manual UV island movement/scaling/rotation;
- UV copy/paste and mirroring;
- layers;
- advanced selections;
- tile/seamless helpers;
- direct 3D painting;
- PBR/normal/roughness/metallic maps;
- Animation Core;
- extensions/plugins API.

### Beta project package limitation

The existing `.addonsstudio` package system predates Texture Core. In Alpha 0.0.4.0, its Texture Core payload is not yet promoted to the portable package contract. Users should treat project-package export/import as Model Core-focused beta functionality until a later 0.0.4.x package revision explicitly adds materials, texture images, and face bindings.

Local IndexedDB projects do persist Texture Core data normally.

## Verification

The 0.0.4.0 foundation is covered by database migration tests plus dedicated TextureRepository tests for:

- material and texture persistence;
- sharing one material across multiple models;
- per-face bindings without geometry mutation;
- edited PNG replacement;
- atomic material/texture/binding deletion.

Release gate: clean install, lint, TypeScript, automated tests, and production PWA build must all remain green before publication.
